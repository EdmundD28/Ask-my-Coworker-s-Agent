# 第一版实施与证据计划

本文是当前实施计划，不是新的产品架构决策。若实施发现必须改变稳定边界，应另建架构决策记录，而不是悄悄改代码。

## 交付路线

### M0：通用核心垂直切片

状态：已完成本地实现；15 项确定性测试通过。尚未验证真实模型和真实网络。

目标：在无外部服务的条件下验证回答行为和隐私边界。

- 只接受由提问方所有者明确触发的问题，不实现推理中自动提问；
- `ANSWER`：现有、可披露资料支持回答；
- `UNKNOWN`：没有足够资料，且不调用生成模型补猜；
- `CONFLICT`：资料冲突且冲突内容可向提问方披露，同时通知回答方真人；
- `REFUSE`：资料或冲突细节不在接收者披露范围内，生成模型不得先行调用；
- 回答携带生成时间和资料版本引用；
- 共享任务状态、开发监视页和审计不出现未获授权的私人原文；
- 第三方发布扩大披露范围时需要相关所有者批准；
- 群主转让只有目标成员主动接受后生效。

证据等级：本地确定性测试。不能声称已经验证真实模型、真实网络或跨所有者环境。

### M1：持久化与本地进程边界

状态：已完成本地实现；完整套件 22 项通过，治理恢复边界修正后受影响测试 1 项通过。

目标：把 M0 从内存替身迁移到可恢复的本地运行形态。

- SQLite 保存空间、任务、最小审计和治理事件；
- A、B 分别运行独立进程和独立私人资料目录；
- 网页监视入口只读取经过筛选的共享投影；
- 重启后任务状态和群主状态可恢复。

证据等级：单机多进程测试。仍不能替代异地验收。

### M2：ACN 真实接入验证

状态：第一位所有者智能体已完成真实接入；当前完整套件 68 项通过。角色名片、入站规则、所有者触发标记、持久化防重放、A2A 接收端、Interfaze 会话回写、一次性邀请自动接入核心、Windows 一站式成员程序、当前 ACN 线协议适配和双端本地消息入口已落地。受邀者加入成功后会自动打开自己的本地消息页；创建者和受邀者使用相同入口主动提问，正文按本机身份写入各自本地数据库，无令牌不能读取。真实 ACN 已创建一个智能体和一个仅含该智能体的私有审批制空间；ACN 服务端已确认公网端点可达且 A2A 握手通过。2026-09-16 已从 Interfaze 页面完成所有者侧端到端验收：普通文本经 ACN 到达本机，接收端用短期智能体令牌把不读取资料、不调用模型的静态连接回执写回原会话，页面自动显示回复。公网直连使用 ACN `open` 传输模式，但 AMCA 入站准入与披露边界保持独立。第二位所有者尚未接入，因此跨所有者传输、异步收件箱恢复和双端正文隔离仍未完成真实验收；Windows 邀请包已经完成离线解包启动验证并增加 ACN 端点解析自动重试，但尚未在第二台独立设备完成真实加入。

目标：判断 ACN 是否适合作为第一版通信实现，而不是预先宣布成功。

- 两个智能体分别注册并保存自己的 ACN 凭据；当前只完成创建者一方，凭据使用 Windows 当前用户数据保护接口加密；
- 使用私有网络邀请和接受流程建立成员关系；
- 通过 ACN 发送 AMCA 问题消息和结果消息；
- 发送动作由提问方所有者明确触发，不以自动推理触发代替冒烟验证；
- 验证发送者、目标、项目范围、时间戳和重放标识；
- 撤销成员资格和重放旧消息必须失败；
- 记录接入步骤、失败证据和普通参与者操作成本。
- 两端接入后自动进入各自本地消息页，并且只能查询本机身份参与的双边会话。

真实外部注册前必须先满足：

- AMCA 问题通过 A2A `DataPart` 承载，不能被 ACN 当成任意字典字符串化；
- AMCA 请求标识、触发来源、项目范围、时间和重放标识在接收侧可解析；
- 入站规则在任何模型调用和私人资料检索之前执行；
- 两个智能体使用相互独立的 ACN API key，不通过单个全局命令行配置轮流覆盖；
- 明确凭据保存方式和两个可接收回调的端点，避免用虚假地址污染公共注册表。

第一位所有者接入证据（2026-09-15）：

- ACN 分配了真实智能体标识，注册状态为在线；身份所有者声明仍是未验证自述，真人认领是独立步骤；
- ACN 的服务端探针返回 `endpoint_reachable=true` 和 `a2a_handshake_ok=true`；
- 公网 AMCA 问题到达正式智能体标识后，在读取资料或调用模型前返回 `ask_human`，符合逐次确认边界；
- 私有空间采用 `is_private=true` 与 `join_policy=approval`，成员列表目前只有创建者智能体；
- 当前入口是临时 Quick Tunnel，只用于接入验证；域名变化后必须更新 ACN 端点。

这份证据只通过了“第一端登记、反向可达和准入拦截”，没有通过“两端真实消息投递”。邀请第二位真人后才继续后半段验收。

若 ACN 限制核心能力或接入成本不可接受，保留相同 AMCA 问答契约并替换通信适配器。

证据等级：真实 ACN 服务的双智能体通信测试；仍不等于真实模型回答质量。

### M3：真实回答运行时

目标：用相同协议接入 Luna，再接入至少一个不同模型或供应商。

- 模型只接收披露检查后允许使用的最小资料；
- 模型不负责身份验证、次数限制或最终发送权限；
- 代表性测试测量支持性、未知拒答、冲突识别、越权披露和真人介入；
- 不把个人 ChatGPT 套餐描述为可跨账户转移的供应商计费能力。

证据等级：真实模型运行记录，必须单独报告错误和未验证风险。

### M4：异地双所有者验收

目标：完成第一版最终验收。

- 两名异地真人；
- 两个真实账户；
- 两个独立设备或运行环境；
- 通过公网加入同一受控协作空间；
- 浏览器只显示各自有权看到的状态和审计；
- 完成问答、拒答/未知、冲突、第三方发布检查和群主转让。

证据等级：第一版最终验收。M0–M3 的通过不能代替本阶段。

## ACN 架构采用清单

| ACN 成熟做法 | AMCA 的采用方式 | 明确不继承的含义 |
|---|---|---|
| 注册、发现、传输分离 | 放入可替换的网络适配器 | 注册成功不代表身份已验证 |
| 结构化消息信封 | 定义版本化问题和结果消息 | 收到消息不代表可以读取私人资料 |
| 路由层、服务层、基础设施层分离 | 核心服务不直接发 HTTP | ACN 路由策略不等于披露策略 |
| 结构化审计 | 记录参与方、状态、时间和最小原因 | 不复制未发送的私人资料原文 |
| 健康检查 | 为开发监视入口提供健康状态 | 健康不等于远程闭环验收通过 |

## 当前明确不做

- 完整群聊或“智能体版办公聊天软件”；
- 复杂授权编辑器；
- 正式身份凭证体系；
- 结算、跨账户额度转移或商业模式；
- 为某个电机、代码库或办公流程硬编码字段和答案；
- 推理中自动决定向其他智能体提问。
