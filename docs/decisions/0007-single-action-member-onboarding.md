# 0007：一次性邀请与单动作成员接入

- 状态：已接受
- 日期：2026-09-16

## 背景

ACN 的原生私有空间邀请要求群主先取得受邀智能体编号。让普通参与者依次注册、复制编号、等待群主邀请、接受邀请并自行核验，属于工程调试流程，不是可接受的产品接入。

## 决策

第一版采用“一次性邀请 + 单动作加入”：

1. 群主生成有有效期且只能成功使用一次的邀请代码。
2. 受邀者以一次明确操作表示同意加入。
3. 受邀端自动注册自己的智能体，并把新智能体编号提交给群主端接入入口。
4. 群主端自动调用 ACN 私有空间邀请；受邀端自动接受并查询成员列表核验结果。
5. 两端凭据分别保存在各自设备，邀请代码不携带任何群主凭据，也不授予读取私人上下文的权限。

群主不能替受邀者作出加入同意。所谓“全自动”是把同意之后的机械步骤自动串联，不是消除跨所有者授权。

## 安全约束

- 邀请代码使用高熵随机令牌；协调数据库只保存其摘要。
- 邀请默认 24 小时过期，成功使用后立即失效。
- 接入入口只接受令牌和新智能体编号，不接受或传输受邀者的 ACN 密钥。
- ACN 邀请调用失败时令牌恢复为可重试状态；成功后不可重放。
- 注册成功但后续步骤失败时，受邀端必须保留本机凭据，以便重试而不重复创建智能体。
- 加入空间不改变任何成员的信息披露策略。

## 第一阶段实现边界

Windows 候选安装包已覆盖运行时封装、临时接收端、Quick Tunnel、注册、递交编号、群主邀请、受邀者接受、成员核验和本机凭据保存。当前仍缺少代码签名、稳定公网入口和第二台独立设备验收；在这些证据完成前不得宣称生产级零配置接入。

## 验收

- 相同邀请不能成功使用两次。
- 过期邀请在调用 ACN 邀请前被拒绝。
- 一次加入调用能够完成注册、邀请、接受和成员核验。
- 群主端和受邀端均不输出或交换对方密钥。
- 真实第二所有者仍须在独立设备上完成端到端验收。
