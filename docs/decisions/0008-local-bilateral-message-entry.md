# 0008：双端本地消息入口与参与者可见性

- 状态：已接受
- 日期：2026-09-16
- 范围：第一版双端提问入口、本地会话保存和页面访问边界

## 背景

一次性邀请已经把受邀者接入、凭据保存和公网接收端启动串成一个动作，但接入成功后仍只有工程进程，没有普通参与者可用的消息入口。若继续优先扩展安装器，只会把“安装成功但无处使用”的缺口包装得更精致。

第一版已经确定只允许所有者明确触发提问，并采用双边私聊加最小共享任务状态。因此下一步应让每个参与者在自己的设备上进入相同的本地消息页，而不是让所有人共用一个能读取全部正文的中央网页。

## 决策

### 1. 每个成员节点都提供自己的本地消息页

- 受邀者完成一次性加入后，成员程序自动打开其本机 `127.0.0.1` 消息页。
- 创建者侧接收端在加载了有效私有空间凭据时，也提供并默认打开相同的本地消息页；无人值守运行可以显式关闭自动打开。
- 页面属于成员节点，不属于 ACN，也不是中央协调空间的正文管理后台。

### 2. 双方都可以由所有者主动发起提问

- 页面从当前私有空间的成员列表中选择回答方；不能选择本机智能体，也不能向空间外标识发起问题。
- 页面提交的消息始终标记为“所有者明确触发”，继续遵守决策 0006；界面不引入智能体自动提问。
- 发送继续使用版本化 `amca.question.v1` 契约和可替换通信适配器。
- 直接投递返回的结构化回答写入发送方本地会话；只返回已接受或收件箱状态时，页面只显示投递状态，不伪造回答。

### 3. 正文只保存在参与者自己的本地会话账本

- 每个节点使用自己的本地消息数据库保存本机参与的提问和回答。
- 会话参与者由本机智能体标识和对方智能体标识在服务端确定，不能由浏览器自行声明。
- 第一版一对成员对应一个稳定的双边会话标识；标识由排序后的双方智能体标识派生，因此 A→B 与 B→A 进入同一会话。
- 会话和消息查询始终绑定当前节点的本机智能体标识。第三个智能体即使知道会话标识，也不能通过本地消息接口读取该会话。
- 协调数据库继续只保存最小任务状态和审计，不复制双边问题、回答或未发送的私人资料。

### 4. 本地页面与公网接收入口共享端口时仍须隔离

Quick Tunnel 会把成员节点的接收端口映射到公网，因此不能只凭监听 `127.0.0.1` 判断消息接口安全。

- 节点启动时生成高熵本地访问令牌。
- 自动打开的本地网址把令牌放在网址片段中；片段不随 HTTP 请求发送，并立即转存到当前浏览器标签的会话存储后从地址栏移除。
- 所有返回本机身份、成员和双边正文的接口都要求该令牌；无令牌访问只能取得不含数据的静态页面外壳。
- 页面不加载第三方脚本或资源，并设置禁止外部引用和嵌入的浏览器策略。

## 与既有边界的关系

- 本决策实现决策 0001 的双边正文可见性，不把第一版扩张成多人正文会话。
- 本决策实现决策 0006 的所有者明确触发入口，不恢复第一版自动提问。
- 安装成功只代表本地节点和消息页已启动，不代表第二位真人、第二台设备或公网双向问答已经验收。
- 令牌保护的是当前成员进程暴露的本地网页接口，不是操作系统级多用户隔离、端到端加密或正式账户认证。

## 当前仍未完成

- ACN 把问题放入异步收件箱后，成员节点尚未实现拉取、处理和把结果主动送回原提问方；当前完整回答只覆盖在线直接投递返回。
- “逐次确认”状态可以显示在本地会话中，但本决策不实现确认后恢复处理的审批操作。
- 第二位真人在独立设备上的安装、自动打开、双向主动提问和正文隔离仍须真实验收。
- 稳定公网入口、代码签名、正式本地认证、通知和数据保留策略仍未完成。

## 验收

- 受邀者加入成功后自动打开自己的本地消息页。
- 创建者与受邀者使用同一套页面和提问接口，均能选择对方并主动发起结构化问题。
- A→B 和 B→A 进入相同的双边会话；A→C 进入不同会话。
- 本地接口只返回当前节点参与的会话；空间外收件人和本机自身均不能被选为回答方。
- 无本地访问令牌时无法读取本机身份、成员列表、会话列表或消息正文。
- 协调任务投影和审计仍不包含双边正文。
