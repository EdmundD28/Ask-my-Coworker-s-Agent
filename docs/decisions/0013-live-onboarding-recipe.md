# 决策 0013：以实际接入过程固化配置码与手册

- 日期：2026-09-16
- 状态：创建、邀请加入、会话挑战及真实公网问答往返已验证；跨真人异地验收未完成
- 补充：0012；取代仅以本地测试作为新接入包交付依据的做法

## 用户要求

用户在任务 `01a0a8be-f4e0-72a2-9217-e152765b580b` 再次遇到实际接入失败，要求开发智能体先自行跑通，再将成功过程写成配置码提示词并更新内置手册。本次明确授权真实接入验证，不等于授权安装或使用私人资料。

## 已查明的真实缺陷

1. 可选职责在产品中保存为“未填写”，但外部服务注册接口要求10至500字符。旧版未经转换直接发送，引发HTTP 422。现在由适配器添加中性的产品说明，保留本地名片原文，不编造能力或身份；名称和职责的长度上限在本地校验。
2. 外部服务的字段错误位于 `details.pydantic_errors`，旧版没有读取结构化原因。现在只提取允许的字段名和数字约束，不将输入内容、令牌或原始响应写入诊断。
3. Windows加密凭据绑定安全账户。受限执行环境与获准执行环境混用会导致解密失败，旧版误报离线。现在明确报告本机访问失败，并在启动前验证领取时的安全账户，避免跨账户创建远端状态。

## 实测顺序

界面生成目标码 → 同一工具环境执行 `preflight` → `accept` → 简短确认必要配置 → `validate` → `apply` → `start` → `status`确认三项连接条件 → `agent poll`读取随机挑战 → `agent ack`回复 → 再查 `status`确认会话通道。

环境检查先于领取：检查目标目录可写、Windows凭据加解密和接入服务可达，不注册身份、不创建空间、不消耗接入码。工具限制应使用正式授权机制处理，禁止绕过权限。

配置码包含当前生成程序的实际路径（本机创建/恢复流程）和已验证步骤；受邀码不包含邀请者电脑路径。要求内置手册版本至少4。每次工具调用重新设置路径变量，不假设跨调用保留PowerShell变量。

程序位置必须按设备解析：打包程序使用当前正在运行的可执行文件所在目录；源码开发模式从本机 `dist` 中选择实际存在且最新构建的完整名称程序，不固定任何版本目录。创建/恢复配置码可以包含该设备的实际路径；发给其他所有者的邀请码不得包含邀请者路径，只提示使用接收方自己解压的程序。

HTTP 422 不应原样重试，更不能告诉用户“启动接入服务”；应修复字段或更新程序。请求确未发送可在修复环境后重试。未知创建结果仍保留，禁止删除标记重新注册。

## 证据边界

同一开发会话控制同一电脑的独立创建者和受邀者目录，双方注册为不同真实远端身份，加入同一私有空间，完成各自会话挑战。合成题经真实远端传输进入待确认队列，经验收批准后被当前模型收取并回答，答案再经远端传回并核对。

这验证真实接入与当前工具会话的收发能力，不证明两个独立真人、不同模型供应商或异地设备的闭环，也不提供后台唤醒。验收只使用合成资料，没有安装程序或改写用户旧测试状态。
