# 架构决策 0006：第一版仅允许所有者明确触发提问

- 状态：已接受
- 日期：2026-09-15
- 取代：[决策 0005](0005-automatic-question-trigger-and-no-relay.md) 中“第一版实现自动提问”的范围
- 范围：第一版提问入口和通信协议边界

## 决策

第一版只支持由提问方所有者明确触发的智能体间询问：

1. A 的所有者选择回答方 B，并向 A 给出需要询问的具体问题；
2. A 的智能体通过 AMCA 通信通道向 B 的智能体发送结构化问题；
3. B 的智能体依据自身资料、入站规则和披露权限，返回回答、未知、冲突、拒绝或请求本人介入，并附带原因；
4. 协调空间记录允许共享的通信状态和调试审计。

第一版不允许 A 在推理过程中自行决定并发起对 B 的询问，也不允许 B 自动把问题转问第三方。已经确认的自动提问门槛保留为后续版本的设计基线，不进入第一版实现和验收。

这里的“所有者明确触发”不等于绕开智能体直接进行真人聊天。问题仍须经过 A 的智能体、AMCA 通信边界和 B 的智能体，才能验证跨所有者问答闭环。

## 第一版通信协议边界

第一版规定 AMCA 自己的最小、版本化消息契约，但不把 A2A 或任何特定通信协议规定为产品必须使用的协议。

通信实现只要能够承载该契约，并满足异地送达、参与方识别、重放防护、状态返回和审计要求，就可以作为第一版候选。若 ACN 的现有 A2A 能力满足这些要求且接入成本合理，可以直接采用；否则应替换通信适配器，而不是修改 AMCA 的问答和披露规则迁就协议。

## 理由

第一版先证明“由人明确发起的问题，能够跨两个真实所有者和运行环境安全送达并得到受控回答”。这能把通信、回答、权限和监视问题分开定位，避免自动触发策略掩盖基础闭环缺陷。

把 A2A 保留在适配层，可以复用成熟实现，同时避免把某个协议或供应商能力误写成产品本身的永久优势。

## 后续兼容要求

- 问题消息应保留任务标识、发送方、回答方、问题正文和关联标识，使以后增加自动触发时无需更换核心消息类型。
- 审计记录应区分“所有者明确触发”和未来可能增加的“智能体自动触发”。
- 角色名片继续用于帮助所有者选择 B，但第一版不据此自动路由。
