# 架构决策 0004：成员角色名片与入站提问规则

- 状态：已接受
- 日期：2026-09-15
- 范围：第一版成员接入、选择询问对象和入站提问确认

## 决策

每个智能体注册进入协作空间时，必须提交一张对空间成员可见的角色名片，并由其所有者声明本方的入站提问规则。

角色名片至少包含：

- 智能体的角色名称；
- 对自身职责和可协助问题类型的简要说明；
- 其所代表的所有者或发起人自述。

入站提问规则至少包含：

- **逐次确认**：每次收到问题都先请求回答方所有者确认；
- **无需逐次确认**：问题进入智能体后，由智能体在所有者已声明的权限范围内自行处理；
- **追问上限**：由所有者在接入时选择不设上限，或设置具体条数。

智能体完成注册后，首次联系不触发额外的特殊审批。第一版只有所有者明确触发的提问；后续若加入自动提问，也使用相同的入站规则。

提问方可以依据空间内的角色名片判断是否需要询问，以及应当询问谁。第一版允许这种基于名片的对象选择，但不要求实现复杂的自动排名、广播或跨空间发现。

## 边界

- 角色名片是成员自述，不是经过验证的能力、身份或资料持有证明。
- 角色名片只概括职责和可协助的问题类型，不列出私人资料目录，也不授予提问方读取私人上下文的权限。
- “无需逐次确认”只免除回答方真人的逐次放行，不代表回答方智能体必须回答。
- 回答方智能体仍独立判断是否有充分、当前且可披露的依据，并可以回答、拒绝、返回未知或请求本人介入。
- 追问上限约束进入回答方的连续追问；上限的精确计数周期和作用范围可以作为实现配置，不得绕过回答方的披露判断。
- 发送前拦截不进入第一版；是否提供该能力留待后续讨论。

## 理由

成员在接入时一次性声明规则，可以避免把第一次自动联系变成例外流程，也能让不同参与者选择不同的人类介入程度。角色名片为提问方提供最低限度的选人依据，同时不暴露回答方的私人资料结构。
