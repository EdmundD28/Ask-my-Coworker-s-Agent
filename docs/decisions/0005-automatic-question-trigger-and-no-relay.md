# 架构决策 0005：自动提问门槛与禁止自动转问

- 状态：部分已取代；自动提问移至第一版之后，禁止回答方自动转问仍有效
- 日期：2026-09-15
- 取代记录：[决策 0006](0006-v1-owner-triggered-questions-only.md)
- 范围：后续版本的推理中自动提问基线，以及回答方对第三方的处理

## 决策

后续版本若启用自动提问，A 的智能体同时满足以下条件时，可以在推理过程中自动向 B 提问：

1. A 已检查自己获准使用的项目资料和现有任务状态，仍找不到完成当前任务所需的答案；
2. A 知道 B 明确负责该部分，因此有充分理由判断 B 很可能知道答案。

A 应把缺少的具体信息压缩成最小、可回答的问题，并记录自己为何没有答案、为何选择 B。不能仅以模型自报置信度低作为自动提问理由，也不能因为不知道该问谁而广播问题。

B 在第一版以及后续版本中处理问题时，都不得自动向第三方 C 转问。若 B 判断 C 更适合回答，可以向 A 返回建议，包括建议询问的对象及理由；是否向 C 发起新问题，仍由 A 按自己的提问规则重新判断，或由 A 的所有者明确指定。

## 边界

- A 确认自己没有答案，只限于检查其获准使用的资料；不得为满足门槛而扩大读取范围。
- “B 明确负责该部分”需要来自角色名片、任务分工或其他明确职责信息，而不是无依据猜测。
- 自动提问仍受 A 的发送限制、B 的入站规则、追问上限和披露权限约束。
- B 可以回答、拒绝、返回未知、请求本人介入，或建议 A 改问第三方；A 自动发问不产生 B 的回答义务。
- B 提供第三方建议时，不得泄露 B 无权向 A 披露的资料，也不代表第三方已经同意被询问。

## 理由

这个门槛把自动提问限制在“本方确实缺少必要答案，并且存在职责明确的高概率回答方”这一情形，减少无目的打扰。禁止 B 自动向第三方转问，可以避免形成不可见的多跳通信、权限扩散和循环追问，同时保留由 A 发起下一次明确询问的能力。
