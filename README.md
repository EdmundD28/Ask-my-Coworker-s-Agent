# Ask My Coworker's Agent

**简体中文** | [English](README.en.md)

Ask My Coworker's Agent 让属于不同真人的智能体直接完成双边协作，同时把私人上下文和信息披露权留在各自所有者一侧。

## 本机产品入口

当前用户可双击桌面 **Ask My Coworker's Agent** 快捷方式，或项目根目录的 `打开 Ask My Coworker's Agent.vbs`。该入口使用 `latest` 统一工作区并复用现有“冒烟3”数据。左侧选择空间、成员和历史对话，右侧直接发消息；从“＋ 接入”生成配置码，从顶部操作邀请、待确认问题和空间设置。离线时先点“连接空间”。关闭浏览器后可再次双击入口，无需通过智能体找端口。

## 智能体对话配置测试入口

当前测试版固定覆盖到 `dist/Ask My Coworker's Agent latest/`，不再并列保留版本号目录。双击程序打开本机界面，点击“生成配置码”，把代码交给具有本机文件和命令工具的智能体。接入完成后，创建者可从界面生成绑定该空间的一次性邀请码。智能体读取程序内置手册，无需模型供应商接口、依赖安装或此前对话上下文。

已有本机名片和通用偏好可以复用；新空间的披露权限必须独立确认。接入码不会自动执行；只有智能体按本人授权调用 `start` 后，才启动临时公网隧道和注册操作。旧版本数据和可执行文件不参与新测试。配置保存、通讯连接及会话挑战验证分别报告。智能体可以主动收取问题并回复，但程序不能唤醒关闭的模型对话。详细边界见 [决策 0011](docs/decisions/0011-ui-generated-entry-and-agent-session-binding.md)。

第一版只证明一件关键事情：A 的所有者明确要求自己的智能体向 B 提问；B 的智能体在自己的边界内查找依据，然后回答、返回未知、暴露可披露的资料冲突，或因边界拒绝。协调空间负责送达、最小共享状态和审计，不取得 B 的私人资料读取权。推理中自动提问推迟到后续版本。

简化接入及网络恢复规则见 [决策 0012](docs/decisions/0012-conditional-setup-and-network-recovery.md)。首次按分支询问，逐次确认不问成员编号，不限次数不问重置周期；可选项在一次摘要中确认。旧版不明结果的注册记录仍需服务端核对，不应删除后重建。

v4已完成真实创建、邀请加入、会话挑战和合成问答公网往返；最终便携程序也已从新目录实际接入。见 [真实接入验证](docs/SETUP_V4_TEST_RECEIPT.md)。这些证据尚不等于两位真人异地验收。

## 当前实现状态

M0 本地核心切片已通过 15 项确定性测试，范围包括：

- 场景无关的问答状态与回答结果；
- 回答前的接收者披露检查；
- 资料不足、资料冲突和受限资料处理；
- 不复制未发送私人原文的结构化审计；
- 不包含双边正文的共享任务快照和开发监视入口；
- 需要相关所有者批准的第三方发布检查；
- 群主转让的提出、接受和审计；
- 可替换通信接口和 ACN HTTP 适配器。

M1 已完成 SQLite 持久化、独立回答进程和真正可启动的本地 HTTP 监视服务。M2 已完成安全接入前置和第一位所有者智能体的真实接入，包括角色名片、入站提问规则、所有者明确触发标记、持久化防重放、A2A 接收端、Windows 当前用户加密凭据、Interfaze 会话回写、一次性成员邀请、Windows 一站式成员程序、双端本地消息入口和 ACN 私有网络接口；当前完整套件为 68 项。

2026-09-16 的所有者侧真实接入验证已经证明：Interfaze 消息经 ACN 到达本机公网接收端，接收端使用短期 ACN 智能体令牌把固定状态回执写回原会话，页面自动显示回复；ACN 服务端同时确认端点可达并通过 A2A 握手。私有空间当前仍只包含创建者自己的智能体，因此这个结果不等于跨所有者问答验收通过。下一阶段必须由第二位真人在独立环境中登记自己的智能体、接受邀请并通过 ACN 完成问答。

## 与 ACN 的关系

AMCA 会适当采用 `Agent-Collaboration-Network`（ACN）的成熟架构，而不是复制整个项目：

- 采用注册、发现、传输相互分离的通信边界；
- 采用消息信封、服务层、基础设施适配器和结构化审计的组织方式；
- ACN 适配器遵循当前 `/api/v1/agents/join` 和 `/api/v1/communication/send` 契约；
- 保持 AMCA 核心与 ACN 可替换，避免通信供应商锁定。

第一版规定 AMCA 的最小消息契约，不规定产品必须使用 A2A。ACN 的 A2A 能力只有在满足该契约、异地送达和接入简易性要求时才作为通信实现采用。

两者最重要的边界不能含糊：ACN 决定消息能否送达，AMCA 决定 B 可以查阅什么、可以向谁披露什么，以及何时必须通知真人。加入同一网络不是读取私人上下文的授权。

当前实现参考 ACN 的公开接口和分层思路，没有把 ACN 源文件复制进本仓库。ACN 使用 Apache License 2.0；如果以后直接移植其实现代码，必须同时补齐许可证、归属和修改说明。

## 本地验收

项目核心只要求 Python 3.12，第一批测试不依赖外部服务：

```powershell
python -m unittest discover -s tests -v
```

当前工作区若系统没有全局 `python` 命令，可以临时使用已经存在的 ACN Python 环境：

```powershell
& 'D:\AI\myProject\Agent-Collaboration-Network\.venv\Scripts\python.exe' -m unittest discover -s tests -v
```

这条测试只验证本地核心行为。它不会连接真实 ACN 服务、调用真实模型、启动公网地址，也不会证明异地双账户闭环。

## M1 本地运行形态

M1 把三类数据分开：

- 每个回答方进程只打开自己的私人资料数据库；
- 协调数据库只保存共享任务投影、最小审计和空间治理状态；
- 网页监视服务只打开协调数据库，不加载任何人的私人资料库。

安装项目后，可以在本机启动监视服务：

```powershell
amca-monitor --database data/coordinator.sqlite3 --host 127.0.0.1 --port 8000
```

或直接从源码运行：

```powershell
$env:PYTHONPATH = 'src'
python -m amca.server --database data/coordinator.sqlite3 --host 127.0.0.1 --port 8000
```

本地页面地址为 `http://127.0.0.1:8000/`。默认只监听本机；它还没有账户认证，不能因为改成 `0.0.0.0` 就当作安全的公网服务。

## M2 接入边界

第一版的提问只能由提问方所有者明确触发。传输消息必须携带版本、请求和任务标识、提问链、发送方、回答方、项目范围、问题类型、生成时间和重放标识。回答方在读取私人资料或调用模型前，先检查：

- ACN 认证的发送者是否与消息发送者一致；
- 消息是否确实发给本智能体；
- 是否为第一版允许的所有者明确触发；
- 消息是否过期、重复或超过追问上限；
- 提问者、主题和项目是否处于回答方声明的范围；
- 回答方是否要求每次先由本人确认。

角色名片可以向空间成员显示职责、可协助问题类型和所有者自述，但不得公开私人资料目录或具体披露规则。角色名片和第一版所有者触发字段仍是未验证自述，不能宣传成正式身份认证。

第一位所有者智能体已完成真实 ACN 注册。它的 API 密钥保存在 `.amca/acn-owner.json`，由 Windows 数据保护接口绑定当前 Windows 用户加密；命令输出不显示密钥或一次性认领链接。该目录被 Git 忽略。

当前公网入口使用 Cloudflare Quick Tunnel，只适合作为临时接入验证。其随机域名会随隧道重启变化；变化后必须更新 ACN 登记端点，不能把它当作正式部署地址。

每个加载了私有空间凭据的成员节点现在都提供相同的本地双边消息页。受邀者加入成功后会自动打开该页；创建者侧接收端也会默认打开，若用于无人值守运行可添加 `--no-open-chat`。页面允许所有者从当前私有空间成员中选择回答方并主动发起结构化问题。问题和返回结果只写入本机的 `local-chat.sqlite3`，不会进入协调数据库；服务端按当前节点身份筛选会话，浏览器不能自行声明查看者。

本地消息接口使用节点启动时生成的高熵令牌。令牌只放在自动打开网址的片段中，不随 HTTP 请求发送；页面将其保存在当前标签的会话存储中，并从地址栏移除。无令牌访问只能看到不含身份、成员或正文的静态页面。这个机制防止 Quick Tunnel 共享端口直接暴露本地消息接口，但它不是正式账户认证或操作系统级多用户隔离。

核对已登记身份、私有空间及成员：

```powershell
$env:PYTHONPATH = 'src'
python -m amca.pilot inspect --credentials .amca/acn-owner.json
```

对外入口变化后，让 ACN 重新探测并更新端点：

```powershell
$env:PYTHONPATH = 'src'
python -m amca.pilot verify-endpoint --credentials .amca/acn-owner.json
```

群主生成 24 小时内有效、成功后立即失效的一次性邀请代码：

```powershell
$env:PYTHONPATH = 'src'
python -m amca.pilot create-invite --join-url https://<群主公网入口>/onboarding/join
```

源码运行时，受邀者明确同意加入后只执行一次；程序自动注册其智能体、递交编号、接受群主邀请并查询成员列表核验：

```powershell
$env:PYTHONPATH = 'src'
python -m amca.pilot join-invite --invite-code <邀请代码> --endpoint https://<受邀者公网入口>/a2a
```

面向普通参与者的 Windows 一站式包会把 Python 运行时、AMCA 成员程序和 `cloudflared` 封进一个可执行文件。群主生成的压缩包还包含一次性邀请和双击启动入口；受邀者不需要预装 Python，也不需要手工创建公网端点。成员程序会先启动临时接收端和 Quick Tunnel，再自动完成注册、邀请、接受、核验和本机凭据保存。若新 Quick Tunnel 地址尚未传播到 ACN 的解析节点，程序会只针对该端点解析错误自动等待并重试，最长三分钟。

```powershell
$env:PYTHONPATH = 'src'
python -m amca.pilot build-invite-package --member-exe dist/bin/AMCA-member.exe --join-url https://<群主公网入口>/onboarding/join
```

当前可执行文件尚未代码签名，Quick Tunnel 也不是稳定部署地址；真实第二台 Windows 设备仍需完成最终验收。因此它是“单包、双击、自动接入”的候选版本，不应宣传成已经完成生产级安装。邀请只建立空间成员关系，不授予对方读取本机资料、凭据或私人上下文的权限。

当前在线直接投递返回的结构化回答可以立即写回提问方本地会话；若 ACN 只返回异步收件箱状态，页面只显示投递状态。收件箱拉取、延迟处理和把结果主动送回原提问方尚未实现，不能把“已进入收件箱”显示成“已回答”。逐次确认请求可以显示，但确认后恢复处理的操作也仍待实现。

Interfaze 普通文本消息只用于所有者侧连接检查：接收端返回可见的在线状态，不把普通文本自动升级为跨智能体问题，也不读取私人资料或调用模型。回写沿用 ACN 的成熟边界：严格校验会话标识和 `/api/chats/{chat_id}/agent-messages` 路径，用长期 ACN 密钥换取短期智能体令牌后再写回；长期密钥不进入浏览器、日志或回复。真正的 AMCA 提问仍只接受版本化 `DataPart`。

公网直连端点使用 ACN `open` 传输模式，使 Interfaze 和 ACN 能主动投递。这里的 `open` 只表示传输入口开放，不代表 AMCA 披露授权；入站问题仍在资料检索和模型调用前执行 AMCA 自己的准入检查。
